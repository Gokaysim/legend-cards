# Domain reference

What Legend Card Manager is about, what its words mean, and how the original app behaved. For how the code is written, see [conventions.md](conventions.md).

## The product

Our DM runs a **side card system** on top of a D&D 5e campaign:

- Players earn **Legend Points (LP)**. They work much like inspiration: the DM hands them out at the table for good play, and players spend them.
- With LP, players buy **packs** and pick **cards** from them. A card has an effect that the table applies in play: a bonus, a twist, or a risk.
- Some cards are **Cursed**: a player gets them as a price or a punishment. A few rare cards are **Blessed**.
- Players can also learn **True Words**, a separate kind of power with its own draft.
- A player can build a one-off **Custom Card** from effect pieces in a **Custom Card Draft**. The **Elixir Shop** lists **Elixirs**, which change cards themselves.

**Legend Card Manager is a tracker, not a game engine.** The DM and the players make the decisions at the table. The app records them:

- who holds which card
- how many LP each player has
- which effects are active
- what happened, in a log

It does not enforce D&D rules or the table rules, and it never spends LP on its own.

The original app was a single offline HTML file used on one computer. The new app is online and real-time, so the DM and the players can use it together from their own devices.

### Actors

| Actor                   | Role                                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------------------------- |
| **DM** (Dungeon Master) | Runs the game, gives out and takes away LP, decides when packs are opened, and maintains the card data. |
| **Player**              | A member of the group with a hand of cards, an LP balance, and learned True Words.                      |

In the legacy app, the DM operated everything alone and players were just names in a list. The new app signs people in with Google:

- **There is one group.** Everyone who signs in is a player in it and gets a profile with their Google name and picture.
- **The DM is set by an admin script** (`npm run set-role`), never from the app. In the owner's words, "admin" and "DM" are the same role.
- **Every signed-in user can see everything**, including the other players' profiles, cards and player notes. The one exception is the **DM note**: only the DM reads it (`add-player-notes`).
- **Only the DM edits** the card data and does the DM-only card actions. Players do some card actions for themselves, such as opening packs and using their cards. These arrive with the later card changes.

The agreed target model for the coming changes is in the design of the OpenSpec change `add-user-roles` (after it is archived: `openspec/changes/archive/*-add-user-roles/design.md`, "Target data model"). It covers:

- the card library (`cards`), where each normal card records whether it is in the pool or with a player
- the permanent history of who held which card (`userCards`)
- pack openings and draws (`draws`)
- the party's shared GP (`party/main`)
- the LP and GP history (`ledger`)

Each change adds its path to this table.

Card holdings refine the target model too:

- There is no `initial` way of giving. At the very end, before going live, the DM enters the table's current hands with the normal "give a card" action.
- `drawId` and the way `draw` arrived with `add-card-draws`, and the way `pack` with `add-pack-shop`.
- `cardKind`, `transferredFrom` and `transferredTo` are new. They let the rules check both sides of a movement without querying, and they let a later history screen follow a card from hand to hand.
- A DM's extra copy of a held normal card is a holding of its own that leaves the card's `holder` alone. When the holder's holding closes, the card returns to the pool even while an extra copy is still in a hand.

Balances refine the target model too:

- The target model's `reason: manual | pack | draw` is called `source`. `reason` is the DM's own text, which the interface calls "Neden".
- `lpEntryId` and `gpEntryId` are new. They let the rules find the entry that explains a balance without querying, as `holder.userCardId` does for cards.
- The party purse's account in the ledger is the fixed string `party`.
- `drawId` and the source `draw` arrived with `add-card-draws`, and the source `pack` with `add-pack-shop`.
- A draw or pack entry's `reason` is `null`. "Neden" is for the DM's changes by hand, and the draw or pack itself explains its entries.

Draws refine the target model too (`add-card-draws`):

- A random or Cursed draw takes its single card at once. So it stores the card and its holding directly, and leaves out the target's `offered[]`, `chosen[]`, `status`, `createdAt` and `chosenAt`. Packs have their own version of those (below).
- `by` is new: the DM can draw into a player's hand.
- `filters` is new: it shows in the log what the DM drew from.
- `entryId` is new: it lets the rules find the payment without a query, as `lpEntryId` and `holder.userCardId` do.
- Each draw is one card, with its own holding and payment. A player pays and takes each card at once.

Packs refine the target model too (`add-pack-shop`):

- `table/main` is new. Only one pack is open at a time, and while it is open the whole table waits: no card or balance moves except by that pack's own steps. So the shown cards need no reservation in `holder`.
- `offered` holds card IDs only, in the order shown. `chosen` is one card and its holding, and `cursed` is the mandatory Cursed card of a Cursed type and its holding. Their names are stored, as holdings store them.
- `revealed` is new: the positions turned face up, so every device turns them at the same time.
- The status `abandoned` is `cancelled`: a player cannot leave an open pack, and only the DM ends one without a choice, which refunds its payment (`refundEntryId`).
- The target's `createdAt` is `at`, as for draws. `chosenAt` is `closedAt`, with `closedBy`, for a choice and a cancel alike.
- `packTitle` is not stored. `packType` with `setCode` or `mechanicPack` gives the title, which is interface text.
- `cost` is the amount actually paid, in the currency of `paidWith`. A player pays exactly the pack's LP price. The DM chooses the player's LP or the party's GP and any amount, which starts at the price; 0 is free. This replaces the target's "A DM's openings cost nothing", and only the DM pays with GP.

True Words extend the target model (`add-true-words`):

- The target model did not cover True Words. `trueWords`, `userTrueWords`, `playerWords` and `wordDrafts` are new.
- A draft is not stored in `draws`: it shows words, not cards, and its rules stay apart. Its ledger entries still name it in `drawId`.
- `playerWords` exists because the rules cannot query: it gives the price (1 plus `known`'s size), "no word twice" and "one open draft" with one read, as `lpEntryId` and `holder.userCardId` do for balances and cards.
- Taking a word back closes its record. Learning the same word again opens a new record, so the history keeps both.

Player notes extend the target model (`add-player-notes`):

- The target model did not cover notes. `playerNotes` and `dmNotes` are new. The legacy app had one "Oyuncu Notları" box per player, which only the DM used.
- They are not fields on `users/{uid}`. A rule allows or denies a whole document, so a DM note there would be readable by everyone, and the profile rule already has enough exceptions.
- The document ID is the player's uid, so a note is read and written without a query. A save writes the whole note, so the last save wins, as for card notes.

Definition editing extends the target model (`add-card-and-word-editing`):

- `status` (`draft`, `active`, `retired`) replaces the `retired` flag on cards and True Words. Drafts stay in the same collections, so publishing keeps the ID, the picture and any later holdings.
- `changeId` and `definitionChanges` are new. Each DM step writes its record in the same request, as a balance points at its ledger entry, and the İşlem Logu reads the records.
- The read rules differ by status, so a player's device asks only for active and retired definitions (`where('status', 'in', ['active', 'retired'])`), and the DM's device for all of them.

The card library refines the target model in three ways:

- The set field is `setCode`, as agreed in `docs/conventions.md`.
- Rarity is stored in lowercase (`common`, `rare`), and the interface shows "Common" and "Rare".
- "Blessed" and "Cursed" in the CSV Set column are markers, not sets. They become the card's `kind`, and its `setCode` is empty (`null`). Blessed and Cursed cards have no rarity, and Cursed cards have no mechanic pack.

More pack rules:

- The Pandemonium set has no Standard, Premium or Cursed pack. It has the Pandemonium Pack and the Pandemonium Cursed Pack, shown as its own group under Set Packs, last in the stored order.
- The Mechanic Packs section shows one price for all Mechanic Packs, in its heading ("4 LP / 10.000 GP"). The mechanic pack tiles have no price of their own. The Golden Packs group is the last tile in that section. Inside it, the Golden and the Cursed Golden Pack show their own prices.
- Opening a pack shows an animation first: the cardback swells in three pulses of growing strength, then bursts. Set packs, Pandemonium included, use the set's cardback. Mechanic and Golden packs use their pack artwork. The choice grid appears only after the animation finishes. (v2.1.15 showed the pack tearing in two instead.)
- **Every card must be flipped before anything can be chosen.** Clicking a face-down card flips it. Clicking a face-up card before all cards are flipped only shows a reminder.
- Revealing a Blessed card triggers the "shocked" Cardmaker animation.
- In Cursed, Cursed Golden and Pandemonium Cursed Packs, the cursed card cannot be chosen or refused. It is added automatically together with the chosen card.
- Opening a pack never changes the player's LP. The DM adjusts LP by hand. (The new app takes the payment when a pack opens: see [Deliberate decisions](#deliberate-decisions-do-not-fix).)
- A set's packs are shown in a fixed order (see [Sets](#sets)), and a set's group in the shop shows that set's Cardmaker.
- The Pack Shop is reached from the Shops screen, and directly from the "🎁 Pack Shop" button on the hand screen.

The new app (`add-pack-shop`) keeps these rules and the thresholds, with these differences:

- **Blessed cards in the rare packs.** The Golden, Cursed Golden, Pandemonium and Pandemonium Cursed Packs draw their 5 cards from their Rares together with every Blessed card, each with the same chance. The Golden Pack's 2% slot is gone. The thresholds still count only the Rares.
- **Payment.** A player opens a pack into their own hand and pays its LP price when it opens. The DM opens a pack into any hand and charges the player's LP or the party's GP, starting at the pack's price; any whole amount is allowed, and 0 opens it for free. Only the DM pays with GP.
- **One open pack, and the table waits.** While a pack is open, nobody moves a card or a balance, and everyone sees the pack and each card turned over, live.
- **Choosing and cancelling.** The hand's owner or the DM turns the cards over and chooses. A player cannot leave an open pack; only the DM cancels it, which gives no card and refunds the payment.
- **Pictures.** Since `add-card-images`, cards, cardbacks, packs, True Words and the Cardmaker show the owner's pictures (see [Pictures](#pictures)), and a revealed Blessed card brings the shocked Cardmaker pair. Since `add-visual-effects`, the opening burst shows the set's cardback, or the pack's own picture for the other packs, swelling brighter inside a halo of light until the screen flashes warm white, as in v2.2.8.

### Pool, hands and drawing

- Each normal card has at most **one** copy in the pool. Drawing it or choosing it from a pack moves it into a hand, and returning it puts it back. Returning a card never duplicates it in the pool.
- The DM can drag a card from the library onto a player. This can create an extra hand copy of a normal card, as a deliberate DM override.
- A hand card can be dragged onto another player's name to transfer it, after a confirmation. This works for every kind of hand card, Custom Cards included.
- Cursed and Blessed cards are **repeatable**. Holding one never removes it from the pool or the Cursed Deck.
- A random batch draw picks each card uniformly from the available cards that match its filters. It never offers the same normal card twice in one batch. Blessed cards are always available, so they come up in random draws at their share of the pool. With the owner's data (19 Blessed cards among 591), that is about 3% per card with a full pool, and more as the pool shrinks.
- Hand order is the order the cards were received.
- **The hand screen.** v2.2.8 lays it out in this order. On top are six stat tiles: the Cursed tile is red and the True Words tile purple, and "Aktif efekt ⓘ" and "Farklı set ⓘ" open their lists. The tabs stand beside the tiles. Under them is the hand, with the active True Words peeking out above it, and the player's notes. The selected card's details are in a "Seçili Kart" panel at the right. The new app follows this from 2026-11-11 (`align-hand-screen-with-v2-2-8`). It keeps the panel to windows at least 1024 px wide; narrower windows open the details in a dialog. LP stays a "± LP" button with a reason, instead of v2.2.8's amount field in the panel. On 2026-11-12 (`redesign-selected-card-panel`), the owner chose the "V1 · Vitrin" look for the details, after comparing three directions on a design canvas: a small "Seçili Kart" label with the card's marks as badges ("Aktif", "Ek kopya"); the card large across the panel, glowing in its own color over a soft light; labels for the set, rarity, cost and mechanic pack instead of grey lines, and the name and text not written again under a picture; who holds it; the card note on cream paper, like the scrolls printed on the cards; "Kullan" across the panel; and the DM's cost, active switch, giving away and discarding in their own "DM araçları" section. Without a selection, the panel shows an empty card slot with "Bir kart seç". The dialog on narrower windows, and the "Seçili True Word" panel and dialog, use the same pieces.
- A card leaves the hand through "↩ Havuza gönder" in its details, which puts a normal card back in the pool. The new app splits this into "Kullan" (the holder or the DM; it asks, optionally, on which character the card was used) and "At" (the DM only; discarded without use). Since `add-characters`, the character is chosen from a list of the table's characters, grouped by owner with the holder's first, or typed through "Başka (yaz)…" for an enemy or an NPC without a record. Both put a normal card back in the pool.

### LP, cost and effects

- LP changes only through the DM's manual plus and minus actions, by a chosen positive amount. Each change is logged. The new app keeps this for the DM, needs a reason for every change, and never lets LP go below 0. It also takes the payments the rules page names: draws, packs, True Word drafts, and, since `pay-lp-on-use`, using a card or a True Word (see [Deliberate decisions](#deliberate-decisions-do-not-fix)).
- Card costs keep their written form (`X`, `d6`, and so on). A cost override applies to one hand card, not to the card definition.
- Any hand card and any learned True Word can be switched active or inactive.

### True Words

- True Words have their own list: a name and an effect text, imported from their own CSV.
- A draft needs at least 3 True Words that the player has not learned yet. It shows 3 of them at random, and the player learns 1 or skips the draft. A skip is logged.
- A player cannot learn the same True Word twice.

The new app (`add-true-words`) adds to this:

- **The list.** `npm run import-true-words` loads `data/true-words.csv`. Each word keeps its **cost as written** (`0` to `5`, or `X`): the LP a player pays at the table each time they use the word, as the rules page says. The legacy app ignored the Cost column. Since `pay-lp-on-use`, using a word charges it, as using a card does; the word stays with the player.
- **The draft costs 1 LP plus the number of True Words the player knows**, as the rules page says. A player starts a draft only for themselves and pays the price from their own LP when it starts. The DM starts one for any player, for the price, another amount of that player's LP, or free (0). A draft is never paid with GP.
- **One open draft per player.** A draft is saved when it starts. Closing the window or reloading never ends it. It ends when the player or the DM learns one of its words, when either of them chooses "Pas Geç" (the payment is not refunded), or when the DM cancels it, which refunds the payment. Everyone sees an open draft live.
- **The DM teaches and takes back.** The DM can teach any active word directly, for free; this is how the table's current True Words are entered before going live. The DM can take back a learned word to correct a mistake: its record is closed, never deleted, and the word can be learned again later with a new record.
- **Active.** Only the DM switches a learned word active or inactive, as for cards. Active words count as active effects in the hand's summary.
- **Retired words** stay with the players who know them. No draft shows them and the DM cannot teach them.

### Custom Card Draft

- **Effects data.** Custom effects come from a CSV with the columns `name`, `1-cost version`, `3-cost version`, and `5-cost version`.
  - Each row is one effect type, and each cost column holds the text of that cost variant.
  - Rows whose name is not one of the 18 effect types are skipped, and so are empty cells.
  - Importing again updates the existing variants.
- **Effect types.** There are 18: Blessed, Caster, Combat, Cursed, Damage, Discard, Draw, Effects, Enhance, Gain, Gold, Held, Reduce, Restore, Roll, Special, TW, XP. The card costs are 1, 3 and 5.
- **Starting.** A draft needs a selected player and at least one loaded effect variant. The player first picks the card's cost: 1, 3 or 5.
- **Each step.** The draft shows up to 3 random effect types, drawn from the types not picked yet that have a text for the current cost, and the player picks 1.
  - There is no reroll and no skip. A draft can only be cancelled.
  - When no option is left, the draft says that the CSV is incomplete and has to be cancelled.
- **Number of picks.** A Custom Card needs 3 different effects.
  - Picking **Effects** adds 2 more picks.
  - Picking **Special** in a 3-cost draft adds 2 more picks, which use the 1-cost variants. From the third pick on, the next picks use the 1-cost variants until those 2 are used.
- **Special at 5 cost.** When the card is finished, every other effect uses its 1-cost text.
- **Special at 1 cost.** When the card is finished, one random other effect that has a 3-cost text uses that 3-cost text instead.
- **The finished card:**
  - Its name is "`<cost>`-Cost Custom Card". Its set is `Custom`, its rarity `Custom`, its mechanic pack `Custom Draft`, and its cost the chosen cost.
  - Its text lists each effect as "`<Type> (<cost>-Cost): <text>`".
  - It goes to the end of the player's hand, the draft is logged, and the app switches to that hand.
  - If any resolved effect has no text, the card cannot be finished.
- **Lifecycle.** Custom Cards are never in the pool, the library, or a pack.
  - Returning one destroys it: the button reads "✕ Custom kartı yok et" instead of "↩ Havuza gönder".
  - Its definition is deleted once no hand holds it. Deleting a player destroys their Custom Cards the same way.
- **Picture.** A Custom Card shows the cover for its cost. Hovering over it cycles through the pictures of its effects.
- **LP.** The app does not charge LP for a draft, because LP is changed by hand. The rules page does not name a price for it.

### Elixir Shop

- Elixirs come from a CSV with the columns `Name`, `Cost`, and `Effect`. Importing again updates the elixirs that have the same name.
- The Elixir Shop shows each elixir as a tile with its picture, name, cost, and effect. Buying an elixir is not recorded; the DM handles it at the table.
- The last tile is **Elixir Withdrawal**, a special Cursed card:
  - "Oyuncunun Eline Ekle" adds it to the selected player's hand and logs it.
  - It can be added any number of times, to any number of players.
  - It is not in the Cursed Deck and is never drawn.
  - It counts toward the player's cursed-card total.
  - Returning it only removes it from the hand.
- Clearing the elixir list does not remove Elixir Withdrawal from any hand.

### Data and history

- **Card data.** In the legacy app, card data came from a CSV with the columns `name`, `set`, `cost`, `rarity`, `text`, and `mechanic pack`.
  - Cursed cards came from a separate CSV.
  - Importing again updates cards with the same name.
  - Other columns, such as `Drawn?` and `Shuffle` in the owner's card sheet, were ignored.
- **Imports.** All imports are on Veri / Yedek, under "CSV ve Görsel Yönetimi": Legend Cards, Cursed Cards, True Words, Elixir Shop, Custom Card Effects, and one bulk picture import. In v2.1.15 the library, the Cursed Deck, the True Words screen, and the Pack Shop had their own import buttons.
- **Clearing.** Each dataset there also has its own "Belleği Temizle" (clear) button.
  - Clearing asks for confirmation and shows the record count. It can be undone with Undo in the same session, and it is logged.
  - Players, LP and notes are always kept.
  - What each button removes:

## Table rules (Kurallar page)

The v2.2.8 rules page (`rulesPage`) has the Cardmaker explain the rules that the players follow at the table. They are summarized here in English.

The app's Kurallar screen (`add-rules-page`) shows the same text in Turkish, as static text in the app. The owner had it rewritten where it disagreed with the app; the Blessed bullets below say how. Its headings are also in Turkish ("Cursed Kartlar", "Kart Çekmek", "Takas", "Blessed Kart Kuralları", "True Word Kuralları"), and a few typos are fixed. See [Deliberate decisions](#deliberate-decisions-do-not-fix).

> **The app records; it does not enforce.** Like the observed rules above, a table rule becomes binding for the new app only when a spec adopts it. Where a table rule disagreed with what the app does, the owner's decision is in [Deliberate decisions](#deliberate-decisions-do-not-fix). A disagreement that is not decided yet goes to [Open questions for the DM](#open-questions-for-the-dm).

### Legend Points

- Players earn LP for legendary play: a memorable heroic deed, a dangerous adventure, or something that makes the game more fun for the whole table.
- Spending 1 LP gives advantage on a d20 roll.
- Spending 1 LP draws a card.
- Using a card costs the LP shown in its top-left corner.

### Using and trading cards

- Players can trade cards with each other, but only one for one. Giving a card away for nothing is not allowed.
- A player can also open a Card Pack from the shop and keeps one card from it.
- Drawing and trading happen only at the start or the end of a game session, never in the middle.
- A card can be used at any time during play, even on another player's turn.
- A used card goes back to the deck and can be drawn again later.

### Card colors

- Purple frame: Common.
- Gold frame: Rare.
- White frame: Blessed.
- Red frame: Cursed.

### Cursed cards

- After a d20 roll the player does not like, they can draw a Cursed card and roll that d20 again. If the die showed a 1, they must draw two Cursed cards.
- Each player can make this bargain once per encounter.
- Cursed cards have their own deck. They never come from among the normal Legend Point cards.
- Cursed cards cannot be traded or given away.
- A Cursed card leaves the hand by being played like any other card, but not during the encounter in which it was drawn. Effects that make a player discard cards can also remove it.
- Cursed cards are unlimited: the same Cursed card can be drawn again and again.

### Blessed cards

- A Blessed card can come from a draw paid with LP, from packs, or as a reward for good play.
- The chance of finding a Blessed card in a normal draw is 2%. A Blessed card can only come from spending LP directly on a draw, not from card effects that draw cards. The app does not use the fixed 2%: a random draw gives every drawable card the same chance (see [Deliberate decisions](#deliberate-decisions-do-not-fix)). The Kurallar screen says that instead: every card in the deck has the same chance, Blessed cards among them.
- Blessed cards can also be found in Rare or Mechanic Packs. Each mechanic has its own Blessed card, plus one more for every 50 cards in that mechanic. The Kurallar screen names Mechanic, Golden and Pandemonium Packs instead, as v2.2.8 has no Rare Packs group. It only says that each mechanic has its own Blessed cards: the card data decides how many.
- A player can hold only one Blessed card. On drawing a new one, they keep only one.
- A player loses their Blessed card when they draw a Cursed card, and when they level up.
- A Blessed card can affect only one player. If any effect would make it affect more than one player, the card disappears.
- Blessed cards cannot be traded.
- Blessed cards have no LP cost, so no card or effect that interacts with card costs applies to them.

### True Words

- True Words are not cards. Nothing that affects cards affects True Words, and they do not count for effects that count cards.
- A learned True Word stays with the player. Using it does not send it back to a deck, and it can be used any number of times, paying the LP cost shown in its middle each time.
- A True Word must be used in the first round of a combat, on the player's own turn. Its effect then lasts until the end of that combat. If it was not used in the first round, it cannot be used in that combat.
- Learning starts with a draft: 3 random True Words are shown, and the player learns 1 or skips all three.
- A draft costs 1 LP plus the number of True Words the player already knows.
- Two players can learn the same True Word. A learned True Word cannot be forgotten, and True Words cannot be traded.

## Deliberate decisions (do not fix)

These look odd but are explicit decisions by the DM and the owner. Do not "fix" them unless the owner asks.

- **LP is only changed by hand.** Pack prices are labels, so opening a pack never deducts LP. In the new app, "by hand" means the DM's changes, plus a player's own payment: since `add-card-draws`, a player's random draw costs them 1 LP, paid when the card is drawn. The DM's draws are free; when the DM draws for a player who should pay, the DM lowers that player's LP by hand. Since `add-pack-shop`, a player's own pack costs its LP price, paid when it opens, as agreed in `add-user-roles`. For a pack the DM opens, the DM chooses the player's LP or the party's GP and the amount, which starts at the price; 0 opens it for free. Since `pay-lp-on-use` (2026-11-14), the owner dropped the rest of the legacy "No automatic LP spending": using a card or a True Word pays its cost from the player's LP, as the rules page says. A player pays exactly the price: a whole-number cost as written, nothing for no cost (the Blessed cards), the die rolled at the table for `d6`, and the amount they enter for `X` or any other text. Cursed cards pay too. A player whose LP is below the price cannot use the card or word. The DM's use charges any amount of the player's LP, starting at the price; 0 is free, and table effects that change a cost are settled this way. The app cannot check a die or an `X` against the table; the log shows what was paid. The word stays known after a use.
- **Balances never go below 0.** Neither a player's LP nor the party's GP. Subtracting more is refused. The legacy app let LP go negative; the owner decided against it in `add-legend-points-and-log`.
- **Every LP and GP change needs a reason.** The DM writes it, and the ledger keeps it with the change. The legacy app asked for none.
- **The pack thresholds are what they are**: 9 cards for set packs, 29 for Mechanic Packs, 49 non-blessed Rare cards for Golden, and the others as in the table above.
- **Blessed cards are mixed into the rare packs.** The Golden, Cursed Golden, Pandemonium and Pandemonium Cursed Packs draw their cards from their Rares together with every Blessed card, each with the same chance. This replaces the legacy Golden Pack's 2% Blessed slot. With the owner's data (19 Blessed cards and 151 Rares, 43 of them Pandemonium), about 45% of Golden Packs and 85% of Pandemonium Packs show a Blessed card. The owner decided this in `add-pack-shop`, knowing those numbers, and it settles the open question about Blessed cards in rare packs.
- **A True Word draft costs LP.** The legacy app charged nothing for a draft. The owner chose the rules page's price in `add-true-words`: 1 LP plus the number of words the player knows, paid when the draft starts, from the player's own LP. "Pas Geç" keeps the payment; only the DM's cancel refunds it.
- **The DM can take back a True Word.** The rules page says a learned True Word cannot be forgotten, and players still cannot forget one. The owner decided in `add-true-words` that the DM may take one back to correct a mistake. The record is closed, never deleted, and the log shows it.
- **A True Word draft does not hold the table, but a pack holds the draft.** Two players can know the same word, so a draft keeps nothing from anyone, and others keep playing while it is open. While a pack is open, though, nobody starts, finishes, skips or cancels a draft, and the DM neither teaches nor takes back a word; switching a word active stays possible.
- **The table waits for an open pack.** Only one pack is open at a time. Until it is chosen from or cancelled, nobody, the DM included, draws, opens a pack, moves a card or changes a balance; notes, switching cards active and cost overrides stay possible. A player cannot leave an open pack: only the DM ends one without a choice, which refunds its payment. There is no timeout. The owner decided this in `add-pack-shop`, so that a card shown in an open pack can never be taken elsewhere.
- **A random draw gives every drawable card the same chance, Blessed cards included**, as in the legacy app. Blessed cards are always in the pool, so they come up at their share of it (with the owner's data, 19 among 591 cards, about 3% with a full pool, and more as the pool shrinks). The rules page's fixed 2% is not used, and the Kurallar screen does not state it. The owner decided this in `add-card-draws`.
- **The Kurallar screen follows the app.** The rules page is the DM's text, and the app shows it on the Kurallar screen. Where the text disagreed with the app, the owner had it rewritten in `add-rules-page`, instead of keeping the DM's words with notes next to them:
  - The fixed 2% chance of a Blessed card in a draw is gone. The screen says that every card in the deck has the same chance, Blessed cards among them.
  - "One Blessed card per mechanic, plus one more for every 50 cards" is gone: the card data decides, as it did in the legacy app. With the owner's data, Gambler's Gambit and Risk & Reward have 3 Blessed cards where the formula gives 2, and the other six mechanics match it. This settles the open question about Blessed cards per mechanic.
  - "Rare or Mechanic Packs" became Mechanic, Golden and Pandemonium Packs, the packs whose cards include Blessed cards.
  - The English headings became Turkish, and a few typos were fixed. The Cardmaker's own voice stays as written.

  The text is static in the app, so changing it is a code change. A later change to draws or packs checks it.

- **Picture faces have no CSS frame.** A card face with a picture shows the picture alone, and its printed frame shows the kind, as in v2.2.8. Its state shows as a glow (an active card green, red or pearl white; a held library card soft gold), with its marks kept as text. Only a face without a picture draws the kind's frame color. The owner chose this on 2026-11-10 in `add-visual-effects`; `add-card-images` had kept the frame around the picture.
- **Every pack in a group is named on its tile.** v2.2.8 named only the Pandemonium Pack, the Mechanic Packs and the Golden Packs under their pictures, and put the price above the picture. On 2026-11-11 (`align-pack-shop-with-v2-2-8`), the owner had the Pandemonium Cursed Pack named too, since the two Pandemonium packs share a picture and a price. On 2026-11-12 (`polish-cards-packs-and-mascots`), the owner had every pack in a group show a short name under its picture, with the price under the name: "Standart" (the owner's Turkish spelling, on the tile alone), "Premium" and "Cursed" for a set's packs.
- **The Cardmaker stands in the corner only on a wide screen with a mouse, and never shows on a phone.** v2.2.8 fixes her in the bottom-right corner on every screen and every device. The owner chose on 2026-11-11 (`align-pack-shop-with-v2-2-8`) to do it on the shop screens only, and only where the device has hover and the window is at least 1024 px wide: on a phone, a fixed figure would cover the cards and could never get out of the way. On 2026-11-12 (`polish-cards-packs-and-mascots`), the owner added the Kart kütüphanesi, the Cursed Deck, Kurallar and the unbuilt screens to the corner, and took every Cardmaker off phones, the shocked pair included.
- **The neutral back.** A random draw and a Golden Pack show a neutral back drawn without a picture, the same for every card, because their cards can be of any set, Blessed included. The legacy app showed each card's set back there, which gave a Blessed card away with the Blessed back before it was turned. The owner chose this in `add-card-images`. On 2026-11-12 (`polish-cards-packs-and-mascots`), the owner gave the Mechanic Packs their own pack picture as the back: it is the same for every card of the pack, so it still gives nothing away. The random draw and the Golden Pack keep the neutral back.
- **The DM note is private.** It is the one piece of data that players cannot read, not even the note about themselves, and a player's device never asks for it. The owner chose it in `add-player-notes`, next to the player note that the whole table reads. Because the DM's screen may face the table, the DM note shows only on the DM's own "🔒 DM notu" tab of the hand, and the tab carries no marker, so it never hints that a DM note exists. On 2026-11-11 (`align-hand-screen-with-v2-2-8`), the owner moved the player note under the hand on every tab, as in v2.2.8, and the Notlar tab with its "✎ Notlar •" marker became this DM-only tab.
- **The official set names are a fixed, hardcoded list.** They are not derived from the data.
- **Pandemonium is a rare-only set with its own packs.** It has no Standard, Premium or Cursed Pack. Its Pandemonium Pack and Pandemonium Cursed Pack form their own group under Set Packs. (v2.1.15 listed the Pandemonium Pack under Rare Packs.)
- **Cursed and Blessed cards are repeatable.**
- **Every card in a pack must be flipped** before choosing.
- **The cursed card in a cursed pack is mandatory** (Cursed, Cursed Golden, and Pandemonium Cursed Packs).
- **Custom Cards never enter the pool.** Returning one destroys it.
- **The DM manages the definitions in the app.** Since `add-card-and-word-editing`, the DM adds, edits, publishes, retires, brings back and deletes cards and True Words on the Kart kütüphanesi, the Cursed Deck and the True Words screen. The owner chose this on 2026-11-11:
  - **Drafts are private (option A).** A player's device never receives a draft. A player reads the active and the retired definitions, and the screens show a retired one only where a hand holds it or a player knows it.
  - **The imports only add.** They add what is not stored yet, never change, retire or delete a stored definition, and the stored definitions are the truth from then on. An added definition is active, or a draft when a value its kind uses is empty; `—` means "deliberately none", an empty cell "not filled in yet".
  - **A card's cost is never required.** A card without one shows `—`. A True Word needs its cost.
  - **Status steps wait for an open pack.** Publishing, retiring, bringing back and deleting wait; fixing a text does not.
  - **Every step is logged (option C).** The steps players can see are listed for everyone; work on drafts for the DM only, also after the draft is published.
- **DM-only cards are hidden in the interface only.** Since `add-dm-only-cards` (2026-11-13), the DM can mark any card "Sadece DM verebilir". The owner chose option A: the card's document still reaches the players' devices, because the hands read it, and only the lists leave it out. A curious player could read it with the browser's developer tools. Its change records stay private by the rules, as draft work does; turning the flag on or off is public, because the card is visible to players on one side of it. The flag changes the pool, so turning it on or off waits for an open pack, also on a draft. The imports never write it, and `cards.csv` has no column for it.
- **Undo and the log last for one session only.** Card history no longer does: the new app keeps every holding permanently, closed but never deleted, as agreed in `add-user-roles` ("History is permanent"). There is no undo; a mistake is corrected with the opposite action.
- **The İşlem Logu is permanent.** It is read from the card holdings, the draws and pack openings, the ledger, the True Word drafts, the learned True Words, the True Word uses and the definition change records, never written separately, so it lists every card given, drawn, used, discarded or transferred, every pack opened, every True Word draft, every True Word the DM taught or took back, every True Word used, every LP and GP change, and every change to a card or True Word definition, across sessions and devices. A draw is one event, with its card, its payment and the DM's filters; its holding and its payment are not listed again. A pack is one event too, at the time it was opened, with its payment, the cards it showed, and the chosen and the Cursed card or the DM's cancel and refund; while it is open, it says so. Its holdings, payment and refund are not listed again. A True Word draft is one event as well, at the time it started, with its payment, the 3 words it showed, and the word learned, "pas geçti", or the DM's cancel and refund; its learned word, payment and refund are not listed again. A used card and a used True Word show their payment in their own event; the payment is not listed again. A definition change is one event: the DM's step with each changed field "eski → yeni" (a text by its visible part, or "metnin gizli kısmı değişti"), or a publish with the definition; an import is one event named "Import", with its count and names. Players see only the changes they can see; the DM's work on drafts and on DM-only cards is marked "🔒 Yalnızca DM" and listed for the DM only; turning a card's DM-only flag on or off shows as "DM'e özel: hayır → evet". Definition changes show only without a player filter. Switching a card or a True Word active, notes and cost overrides are current state, not events, so the log does not list them.

## Sets

The sets are stored data that the DM manages on the **Setler** screen (`add-set-management`): each set has a code, an official name, aliases, a place in the shop order, a pack layout, a cardback and a Cardmaker picture. Every player sees the screen; only the DM adds, renames, reorders and deletes a set. The code never changes once the set exists, and a set can be deleted only while no card uses it.

Card data uses the set code. The interface shows the official name. Matching ignores case, accents and spaces, and also accepts the set's aliases. A code that no stored set has is shown as written.

The sets start from `data/sets.csv`, which `npm run import-sets` loads once, with their pictures from the owner's archives. After that the stored sets are the truth: the import only adds sets that are missing. The initial list:

`Blessed` can appear in the set column of Blessed cards. It is a marker, not a set, and it gets no packs. It cannot be a set's code.

**Pack layouts.** A set has either the Standard, Premium and Cursed Packs ("Standart / Premium / Cursed"), or one Pack and one Cursed Pack drawn from its Rares, as Pandemonium has ("Tek paket + Cursed"). The Pandemonium rules below apply to any set with the second layout: its Pack and Cursed Pack are named after the set ("Ballad of Ulagal Pack"), priced as the Pandemonium Packs, and drawn from that set's Rares with the Blessed cards. Each set has its own cardback and Cardmaker picture, stored with the set. In the archives they are named after the set code in lowercase without spaces: `kesqer_cb` and `cardmaker_kesqer`, `cardmaker_theendisnigh`, `cardmaker_pandemonium`, and so on. The DM can replace or remove them in the set form.
